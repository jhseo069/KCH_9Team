## 1. 목적

부지에 재생에너지 발전설비를 설치할 때 **지자체 조례가 정한 이격거리 규정이 실제로 적용되는지**를 판정한다.

2026-09-18부터 「신에너지 및 재생에너지 개발ㆍ이용ㆍ보급 촉진법」 제27조의3이 시행되어 **지자체의 이격거리 조례 적용이 원칙적으로 금지**된다. 그동안 태양광 사업의 최대 인허가 장벽이었던 조례 이격거리가 무력화되는 변화이므로, "이 부지에 조례 이격거리가 아직 걸리는가"가 실무에서 가장 먼저 확인해야 할 항목이 된다.

## 2. 배경 — 법령 실측 조사 결과

### 2-1. 법 제27조의3 전문 (2026-09-16 law.go.kr 조회)

> **제27조의3(재생에너지 발전설비의 이격거리)** [본조신설 2026.3.17]
>
> ① 지방자치단체의 장은 재생에너지 발전설비를 설치하기 위한 「국토의 계획 및 이용에 관한 법률」 제58조에 따른 개발행위허가 시 다음 각 호의 어느 하나에 해당하는 경우 이외에는 이격거리를 적용할 수 없다.
> 1. 「문화유산의 보존 및 활용에 관한 법률」에 따른 역사문화환경 보존지역 또는 보호구역에 해당하는 경우
> 2. 「자연환경보전법」에 따른 생태ㆍ경관보전지역에 해당하는 경우
> 3. 그 밖에 대통령령으로 정하는 경우
>
> ② 제1항에도 불구하고 지방자치단체의 장은 대통령령으로 정하는 기준에 해당하는 경우 그 기준에 따라 이격거리를 적용할 수 있다.
>
> ③ 제2항에도 불구하고 다음 각 호의 어느 하나에 해당하는 경우에는 제2항에 따른 이격거리가 적용되지 아니한다.
> 1. 제27조의2에 따른 주민 참여형 발전설비
> 2. 지붕형 태양광발전설비(건축물이나 구조물의 지붕에 설치하는 것을 말한다)
> 3. 자가소비용 태양광발전설비(「전기사업법」 제2조제18호의 일반용전기설비 및 같은 법 제2조제19호의 자가용전기설비 중 태양광발전설비를 말한다)

출처: `https://www.law.go.kr/DRF/lawService.do?target=law&MST=289777`

### 2-2. 시행일과 적용례 (부칙 제21462호, 2026.3.17)

- **제1조(시행일)** 이 법은 공포 후 6개월이 경과한 날부터 시행한다. (공포일 2026-03-17)
- **제3조(적용례)** 제27조의3의 개정규정은 **이 법 시행 이후 개발행위허가를 신청하는 경우부터** 적용한다.

> **설계상 중요**: 기준 시점은 조례의 고시일이 아니라 **개발행위허가 신청일**이다. 조례가 언제 만들어졌는지와 무관하게, 신청일이 시행일 이후면 제27조의3이 적용된다.

#### 시행일 확정 상태 — 미확정 (2026-09-16 기준)

부칙은 "공포 후 6개월이 경과한 날"이라고만 정한다. 초일불산입 원칙을 적용하면 **2026-09-18**이 되지만, 이를 법령 API로 **직접 확인하지는 못했다**:

- law.go.kr 상세조회가 `efYd`(시행일자) 파라미터를 무시하고 항상 최신 버전(시행일자 20270101)만 반환한다. `OC=test` 데모 접근의 제약으로 보인다.
- 따라서 "2026-09-17 버전에는 제27조의3이 없고 2026-09-18 버전에는 있다"는 식의 실증 확인이 불가능했다.

**처리 방침**: 상수 `STATUTE_EFFECTIVE_DATE = 2026-09-18`을 쓰되, 코드 주석과 본 문서에 "미확인 값"임을 명시한다. 하루 차이로 갈리는 두 분기(R4 → `조건부`, R5-b → `판정불가`)는 **어느 쪽이든 사람 검토를 요구**하므로, 이 불확실성이 "비저촉으로 잘못 단정"하는 위험으로 이어지지는 않는다. 다만 실사용 투입 전에는 법제처 표기로 확정해야 한다(§11).

### 2-3. 시행령 미비 (핵심 제약)

「신에너지 및 재생에너지 개발ㆍ이용ㆍ보급 촉진법 시행령」(MST 284015) 전체 조문을 2026-09-16 기준으로 전수 검색한 결과, **"이격거리"라는 표현이 포함된 조문이 0건**이다.

즉 법 제27조의3 제1항제3호·제2항이 대통령령에 위임한 **구체적 기준(적용 가능 사유, 거리 상한, 주택 호수 등)이 아직 법령 데이터베이스에 존재하지 않는다.**

> **설계 원칙 적용**: 시중 서비스 일부가 "200m / 주택 5호" 같은 수치를 선반영하고 있으나, 이는 현행 법령으로 확인되지 않는다. 본 시스템은 **확인되지 않은 수치를 판정 근거로 사용하지 않는다**(judge.py의 "불확실하면 비저촉으로 단정하지 않는다" 원칙과 동일). 해당 구간은 "판정불가"로 두고 사람 확인을 요구한다.

## 5. 데이터 스키마 — `data/setback_table.csv`

| 컬럼 | 설명 | 예시 |
|---|---|---|
| `sgg_cd` | 시군구코드 (zoning_jeonnam.geojson과 동일 체계) | `12110` |
| `sgg_nm` | 시군구명 | `목포시` |
| `project_type` | 적용 사업 종류 (`태양광`/`육상풍력`/`all`) | `태양광` |
| `target` | 이격 대상 | `주택` / `도로` / `공공시설` |
| `distance_m` | 이격거리(m). 조례에 없으면 공란 | `100` |
| `min_house_count` | 밀집 기준 호수. 해당 없으면 공란 | `10` |
| `ordinance_name` | 조례 정식 명칭 | `목포시 도시계획 조례` |
| `article` | 조문 | `제27조의2` |
| `law_excerpt` | 조문 원문(그대로) | `...` |
| `gosi_date` | 조례 고시일(YYYYMMDD) | `20220315` |
| `source_url` | 자치법규 원문 URL | `https://www.law.go.kr/...` |
| `verified_by` | 확정한 사람 | `서장훈` |
| `verified_at` | 확정일(YYYY-MM-DD) | `2026-09-17` |

**규칙**
- `verified_by`가 비어 있으면 **미확정 초안**으로 간주하고 판정에 사용하지 않는다(판정불가 처리). 자동 수집한 초안을 사람이 검토하기 전에 판정에 쓰는 것을 구조적으로 막는다.
- 조례에 이격거리 규정이 **없는 것으로 확인된** 시군구도 행을 만들되 `distance_m`을 공란으로 두고 `verified_by`를 채운다. "확인했더니 없음"과 "아직 확인 안 함"을 구분하기 위함이다.

## 6. 판정 로직 명세

### 6-1. 출력 상태

기존 `judge.py`의 4개 상태 체계를 그대로 쓴다.

| 상태 | 이격거리 맥락에서의 의미 |
|---|---|
| `비저촉` | 조례 이격거리가 적용되지 않음이 법적으로 확정됨 |
| `조건부` | 이격거리가 적용됨. 실제 저촉 여부는 현장·실측 확인 필요 |
| `판정불가` | 적용 여부를 확정할 수 없음. 사람 확인 필요 |
| `저촉` | (이번 범위에서는 사용하지 않음 — 주택 실측이 없으면 저촉 확정 불가) |

> `저촉`을 내지 않는 이유: 이격거리 저촉은 "반경 내 주택 존재"를 실측해야 확정된다. 그 기능이 범위 밖이므로, 이번 사이클에서 `저촉`을 반환하면 근거 없는 단정이 된다.

### 6-2. 판정 규칙 (우선순위 순)

```
입력: sgg_cd, project_type, apply_date(개발행위허가 신청 예정일, 기본값 = 오늘),
      exemption(주민참여형/지붕형/자가소비용 여부), zone_flags(역사문화환경보존지역·생태경관보전지역 해당 여부)

R1. exemption 에 해당              → 비저촉
    근거: 법 제27조의3제3항 (해당 호)

R2. setback_table 에 해당 시군구 행이 없거나 verified_by 공란  → 판정불가
    사유: "조례 확인 전 — 사람 확인 필요"

R3. 조례에 이격거리 규정 없음(distance_m 공란 + verified_by 있음) → 비저촉
    근거: "해당 지자체 조례에 이격거리 규정 없음(YYYY-MM-DD 확인)"

R4. apply_date < STATUTE_EFFECTIVE_DATE   → 조건부
    근거: 조례 조문 + "법 제27조의3 시행 전 신청분이므로 종전 조례가 그대로 적용"

R5. apply_date >= STATUTE_EFFECTIVE_DATE
    R5-a. zone_flags 에 역사문화환경보존지역 또는 생태·경관보전지역 해당  → 조건부
          근거: 법 제27조의3제1항제1호·제2호 (적용 가능 예외)
    R5-b. 그 외                    → 판정불가
          사유: "법 제27조의3제1항에 따라 원칙적으로 적용 불가하나,
                 같은 조 제1항제3호·제2항이 위임한 대통령령이 아직 확인되지 않음
                 (2026-09-16 기준 시행령에 이격거리 조문 없음) — 사람 확인 필요"

R6. zone_flags 를 확인할 수 없는 경우(데이터 없음) → 판정불가 (R5-a 판단 불가)
```

`STATUTE_EFFECTIVE_DATE`는 잠정 2026-09-18이며 미확정 상태다(§2-2). R4와 R5는 각각 `조건부`·`판정불가`로 **둘 다 사람 검토를 요구**하므로, 경계일 하루가 어긋나도 잘못된 "비저촉"이 나가지는 않는다. 다만 신청일이 2026-09-17~18에 걸리는 경우에는 판정 사유에 "시행일 경계 — 법제처 표기 확인 필요"를 덧붙인다.

**R5-b가 이 설계의 핵심**이다. 법적으로는 "원칙 금지"지만 시행령이 없어 예외 범위를 확정할 수 없다. 여기서 "비저촉"으로 단정하면 실제로 시행령이 그 부지를 예외로 정할 경우 사업자가 잘못된 판단을 하게 된다. 반대로 "저촉"으로 단정하면 이미 무력화된 조례로 사업을 포기하게 만든다. 양쪽 다 위험하므로 판정불가가 맞다.

## 7. 선행 작업 — `law_lookup.py` 가지번호 버그 수정

### 7-1. 현상

`lookup_article_text(법명, "제27조의3")` 호출 시 **제27조(보급사업)의 내용이 반환된다.** 제27조의2를 요청해도 같은 결과다.

### 7-2. 원인

law.go.kr XML은 가지번호 조문을 아래처럼 표현한다.

```xml
<조문단위>
  <조문번호>27</조문번호>
  <조문가지번호>3</조문가지번호>   ← 이 필드를 보지 않고 있음
  ...
</조문단위>
```

현재 파서는 `조문번호`만 비교하므로 `27`인 첫 블록(제27조)을 반환한다. 실측 결과 이 법에만 가지번호 조문이 **31개** 있다.

### 7-3. 수정 방향

- `extract_article_number`가 `제N조의M` 형태를 `(N, M)`으로 분해하도록 확장
- 조문 탐색 시 `조문번호`와 `조문가지번호`를 함께 비교
- 가지번호가 없는 요청(`제27조`)은 `조문가지번호`가 없는 블록에만 매칭 → 기존 동작 유지

### 7-4. 영향 범위

`rule_table.csv`의 기존 14개 규칙 중 가지번호 조문을 쓰는 항목이 있는지 재확인이 필요하다. 있다면 그동안 잘못된 조문을 인용해 왔다는 뜻이므로 **구현 시 전수 재조회**한다.

## 8. 파이프라인·웹앱 통합

- `setback_check`의 결과를 판정표에 **1행**으로 추가한다.
  - 항목: `이격거리(조례)`
  - 판정: 위 상태
  - 근거조문: 조례 조문 + 법 제27조의3
  - 출처: 자치법규 URL
- 웹앱 API(`api/site_judge.py`) 응답에 `setback` 필드를 추가하고, 프론트는 판정표 행으로 렌더링한다.
- 입력값 확장: 현재 웹앱은 주소·사업종류·용량만 받는다. 이격거리 판정에는 **면제 사유(주민참여형/지붕형/자가소비용)** 입력이 필요하므로 체크박스를 추가한다. 허가 신청일은 기본값을 오늘로 두고 선택 입력으로 한다.

## 9. 테스트 전략

`setback_check`는 순수 함수이므로 TDD로 규칙별 테스트를 작성한다. 규칙 식별자(R1~R6)마다 최소 1개.

| # | 테스트 | 기대 |
|---|---|---|
| 1 | 지붕형 태양광 | `비저촉`, rule=R1 |
| 2 | 주민참여형 | `비저촉`, rule=R1 |
| 3 | 미확정(verified_by 공란) 시군구 | `판정불가`, rule=R2 |
| 4 | 조례에 규정 없음(확인 완료) | `비저촉`, rule=R3 |
| 5 | 신청일 2026-09-17 (시행 전) | `조건부`, rule=R4, 조례 수치 포함 |
| 6 | 신청일 2026-09-18 + 생태·경관보전지역 | `조건부`, rule=R5-a |
| 7 | 신청일 2026-09-18 + 일반 지역 | `판정불가`, rule=R5-b |
| 8 | zone_flags 미확인 | `판정불가`, rule=R6 |
| 9 | 경계값: 신청일 == 시행일 당일 | R5 경로 (시행일 당일은 시행 후) |
| 10 | 신청일이 2026-09-17~18 구간 | 사유에 "시행일 경계 — 확인 필요" 포함 |

`law_lookup` 가지번호 수정도 TDD로 진행한다. 기존 픽스처(`sample_law.xml`)에 가지번호 조문 블록을 추가하고, 제27조 요청 시 가지번호 조문이 반환되지 않는지까지 검증한다.

## 10. 데이터 수집 절차

1. `law_lookup.lookup_ordinance_text()`로 전남 22개 시군구의 도시계획 조례를 자동 조회
2. 이격거리 관련 조문을 추출해 `setback_table.csv` 초안 생성 (`verified_by` 공란)
3. 서장훈 매니저가 조문을 읽고 수치를 확정 → `verified_by`, `verified_at` 기입
4. 확정 전까지 해당 시군구는 R2에 따라 자동으로 판정불가 처리되므로, 미완성 상태로 배포해도 잘못된 판정이 나가지 않는다

## 11. 열린 질문 (구현 중 확인 필요)

1. **시행일 확정** — §2-2에 적은 대로 법령 API로는 확인하지 못했다(`efYd` 무시). 잠정값 2026-09-18로 구현하되, 실사용 투입 전 법제처 표기로 확정한다. 확정 시 코드 상수 한 곳만 바꾸면 되도록 설계한다.
2. **조례 조회 커버리지** — 자치법규 API가 22개 시군구 조례를 모두 반환하는지는 실제 조회로 확인한다. 누락 시 해당 시군구는 R2(판정불가)로 남는다.
3. **풍력 조례** — 조례가 태양광과 풍력을 구분하는 경우 `project_type` 행을 분리한다. 구분이 없으면 `all`로 둔다.

## 12. 참고: 벤치마크 대비 차별점

시중 서비스는 이격거리를 "반경 내 주택 카운트 + 하드코딩된 상한값"으로 즉답한다. 본 설계는 **주택 카운트를 뒤로 미루는 대신, 법·조례 위계와 시행령 부재를 정확히 반영**한다.

즉답성은 낮지만, 2026-09-18 법 시행 직후의 과도기에는 **"조례가 아직 유효한가"** 자체가 최대 쟁점이므로 이 접근이 실무적으로 더 안전하다. 주택 실측은 시행령이 확정된 뒤 붙여도 늦지 않다.
