# 지도 중심 화면 개편 설계서 v1.0

작성일: 2026-09-17
대상: `public/index.html`, `api/site_judge.py`
관련: [RE100마켓 기능 역설계 분석서](../../20260916_분석_RE100마켓(신재생%20계통%20지도)%20기능%20역설계%20v1.0.md), [HANDOVER.md](../HANDOVER.md)

## 1. 배경

현재 화면은 폼 하나와 결과표 하나뿐이다. 지도는 코드에 있지만 판정이 끝난 뒤에야
카드 안 작은 박스로 나타난다. 첫 화면에서 볼 것이 없어 빈약해 보인다.

비교 대상(RE100마켓)이 풍부해 보이는 이유는 기능 수가 아니라 **정보구조**다.
지도가 항상 깔려 있고, 좌측 패널에 도구가 묶여 있고, 결과가 탭으로 나뉘어 있어
"여기 더 있다"는 신호가 계속 보인다.

부품은 이미 있다. 2026-09-17에 용도지역 83,660건(전남 전역, 비도시 포함)을
Supabase/PostGIS에 적재했고, 판정 파이프라인도 거기에 연결했다. 이 데이터가
판정에만 쓰이고 화면에는 전혀 드러나지 않는 것이 현재의 가장 큰 낭비다.

## 2. 목표와 비목표

**목표**
- 첫 화면부터 지도가 보이고, 용도지역이 색으로 구분되어 보인다
- 주소를 입력하지 않고 지도를 클릭해도 판정된다
- 판정 결과가 4개 탭(진단 / 용도지역·필지 / 근거 법령 / 이격거리)으로 나뉜다
- 사업 조건 입력이 항상 보이는 자리에 있어 조건을 바꿔가며 여러 번 돌려볼 수 있다

**비목표 (이번 범위 아님)**
- 계통 여유용량, 경사도, 사업성(IRR/NPV) — 데이터 확보가 선행 과제
- 로그인·사용자별 저장 — `SUPABASE_JWKS_URL`은 있으나 이번에 쓰지 않는다
- 전국 확장 — 무료 플랜 용량(500MB)상 전남까지다

## 3. 화면 구조

```
┌─────────────────────────────────────────────────────────────┐
│ 사업 분석자동화   [주소 검색            ]         전남 22개 시군 │
├──────────┬──────────────────────────────────┬───────────────┤
│ 사업 조건 │                                  │ 진단│필지│법령│이격│
│  종류     │                                  ├───────────────┤
│  용량     │         지 도 (전체)              │ 주소           │
│  예외사유 │                                  │ 용도지역        │
│  기준일   │      클릭 → 즉시 판정             │ ───────────── │
│          │                                  │ 건폐율   비저촉 │
│ 지도 레이어│                                  │ 용도지역  저촉  │
│  용도지역 │                                  │ 이격거리 판정불가│
│  위성사진 │  [범례: 6색]                      │               │
└──────────┴──────────────────────────────────┴───────────────┘
```

**좌측 패널**에 입력을 붙박이로 둔다. 조건을 바꿔가며 여러 번 돌려보는 것이 실제
사용 패턴인데, 지금은 그때마다 위로 스크롤해야 한다.

**우측 패널**은 판정 후에 나타난다. 판정 전에는 지도가 화면을 더 넓게 쓴다.

**모바일(폭 768px 미만)**에서는 좌우 패널이 지도 아래로 쌓인다. 좁은 화면에서
3단을 유지하면 지도가 쓸모없이 작아진다.

## 4. 용도지역 레이어

### 4.1 전달 경로

브라우저가 Supabase RPC(`zoning_in_bbox`)를 **직접** 호출한다. Vercel을 거치지 않는다.

- publishable 키는 애초에 브라우저 노출용이고, RLS가 읽기만 허용한다
- 지도를 움직일 때마다 발생하는 잦은 요청이 Vercel 함수 호출 한도와 10초 제한을
  건드리지 않는다
- 판정 요청만 Vercel을 거친다. 판정 로직과 법령 규칙은 서버에 있어야 한다

### 4.2 줌별 동작

| 줌 | 동작 | tolerance(도) | 근거 |
|---|---|---|---|
| ~11 | 불러오지 않음 | — | 전남 전체에 8만 폴리곤. 그려도 뭉개져 안 보인다 |
| 12–13 | 로드 | 0.0005 (~55m) | 시군 단위 조망 |
| 14–15 | 로드 | 0.0002 (~22m) | 읍면 단위 |
| 16+ | 로드 | 0.00005 (~5.5m) | 필지 단위 |

한 번에 `max_rows` 3,000건으로 제한한다. 초과하면 화면에 "이 범위에는 표시할 수
있는 것보다 많은 구역이 있습니다 — 확대하세요"를 띄운다. 조용히 잘라내면 사용자가
지도에 빈 곳을 보고 "용도지역이 없는 땅"으로 오해한다.

### 4.3 색 구분 (6색 + 중립)

용도지역 17종을 전부 다른 색으로 칠하면 읽기 어렵다. 국토계획법 체계대로 묶는다.
분류는 코드 구조에서 기계적으로 나온다(`scripts/zoning_codes.py`의 `zone_category`).

| 대분류 | 전남 건수 | 비고 |
|---|---|---|
| 주거지역 | 2,002 | UQA1xx |
| 상업지역 | 303 | UQA2xx |
| 공업지역 | 240 | UQA3xx |
| 녹지지역 | 1,421 | UQA4xx |
| 관리지역 | 59,384 | UQB — 태양광 부지 최다 |
| 농림·자연환경보전지역 | 20,219 | UQC, UQD |
| 미분류 | 91 | 중립 회색. 세부 용도 미정 |

색상값은 구현 시 정한다. 제약은 두 가지다. 위성사진 위에 얹히므로 **반투명(0.35
내외)**이어야 하고, 인접 분류끼리 명도가 충분히 달라야 한다.

### 4.4 표시용과 판정용의 분리 (중요)

`zoning_in_bbox`가 주는 도형은 **단순화된 것이며 판정에 쓰지 않는다.**
판정은 `zone_at`이 원본 정밀도로 따로 수행한다.

이유: 단순화는 경계선의 점을 줄인다. 줌 12에서는 55m까지 어긋날 수 있다. 화면에서
경계선 바로 옆에 찍은 점이 실제로는 반대편 용도지역일 수 있고, 그대로 판정하면
"비저촉"이 틀리게 나온다. 규제 판정에서 이것은 허용할 수 없는 종류의 오차다.

## 5. 판정 흐름

```
주소 입력 ─→ 브이월드 지오코딩(JSONP, 브라우저) ─→ 지도 이동 ─┐
                                                          ├─→ /api/site_judge?lon&lat
지도 클릭 ────────────────────────────────────────────────┘        │
                                                                   ↓
                                         eum.go.kr 시도 → 실패 시 zone_at(DB)
                                                                   ↓
                                              규칙 매칭 → 판정 → 5열 판정표
```

지오코딩이 브라우저에서 JSONP로 도는 이유는 서버(Vercel)에서 호출하면 막히고
브라우저 `fetch`는 CORS로 막히기 때문이다(HANDOVER.md §5-4/§5-5). 기존 동작을 유지한다.

지도 클릭은 주소 없이 좌표만으로 판정한다. API가 이미 `lon`/`lat`를 받으므로
서버 변경이 거의 없다. 다만 `address`가 비어도 동작하도록 필수값 검사를 완화한다.

## 6. 탭 구성

| 탭 | 내용 | 출처 |
|---|---|---|
| 진단 | 5열 판정표(항목/판정/근거조문/출처/비고) | 기존 `generate_output_table` |
| 용도지역·필지 | 용도지역명·코드·대분류·시군구·고시면적·좌표. eum 성공 시 지목·면적 추가 | `zone_at` / eum |
| 근거 법령 | 판정 근거 조문의 원문 | `law_lookup` (**신규 엔드포인트**) |
| 이격거리 | 적용 규칙(R0~R6)·예외사유·판정기준일·조례 출처 | 기존 `setback_check` 결과 |

`근거 법령` 탭만 서버 작업이 필요하다. 나머지는 이미 응답에 있거나 클라이언트에서
재구성할 수 있다.

### 6.1 엔드포인트 추가 제약

이 Vercel 프로젝트는 `api/` 폴더에 handler 파일을 **하나만** 둘 수 있다
(`pyproject.toml`의 `[tool.vercel] entrypoint`로 고정, `api/README.md` 참고).
파일을 늘리면 라우팅이 깨진다 — 2026-09-16에 실제로 겪었다.

따라서 `site_judge.py` 안에서 `self.path`로 분기한다.

- `/api/site_judge` — 기존 판정 (변경 없음)
- `/api/site_judge/law?law=...&article=...` — 조문 원문

## 7. 오류 처리

핵심 원칙: **지도 레이어 실패가 판정을 막지 않는다.** 서로 다른 경로이고, 색칠이
안 된다고 판정까지 못 할 이유가 없다. 반대로 판정 실패는 반드시 드러나야 한다.

| 상황 | 화면 | 판정 |
|---|---|---|
| 용도지역 레이어 로드 실패 | 지도 위 조용한 안내 배너 | 영향 없음 |
| 폴리곤 3,000건 초과 | "확대하세요" 안내 | 영향 없음 |
| 지오코딩 실패 | 입력란 아래 사유 표시 | 진행 안 함 |
| **DB 자동정지/장애** | **"잠시 후 다시 시도해주세요"** | **판정불가 (사유 명시)** |
| 전남 밖 좌표 | "현재 전남 22개 시군만 지원합니다" | 판정불가 |
| 겹치는 폴리곤 2건 이상 | 후보 목록 표시 | 판정불가 |

**DB 자동정지를 "해당 없음"으로 보이면 안 된다.** 무료 플랜은 1주일 미사용 시
프로젝트가 멈추고, 그 후 첫 접속은 실패하거나 아주 느리다. 이것은 "이 땅에 용도지역이
없다"와 전혀 다른 사실이다. `ZoneDbUnavailable`로 이미 구분해 두었으므로 화면까지
연결하면 된다.

## 8. 테스트

**Python** (기존 pytest, 현재 133개)
- 경로 분기: `/api/site_judge`와 `/api/site_judge/law`가 각각 올바른 처리로 가는지
- 법령 엔드포인트: 조문 조회 성공/실패, OC 키가 응답에 새지 않는지
- 주소 없이 좌표만으로 판정이 도는지

**JavaScript** (Node 24 내장 `node --test`, 패키지 추가 없음)

프론트엔드에 테스트 틀이 없다. 전부를 테스트하려 하면 비용이 크므로, **틀리면
조용히 잘못된 결과를 내는 순수 함수만** 떼어내 `public/map_utils.js`에 두고 검증한다.

- `toleranceForZoom(zoom)` — 줌별 단순화 강도. 표와 어긋나면 지도가 과하게 뭉개지거나 느려진다
- `shouldLoadZoning(zoom)` — 줌 11 이하에서 로드하지 않는지
- `categoryColor(category)` — 7개 분류가 모두 색을 갖는지(미정의 분류가 투명해지지 않는지)
- `bboxOf(map)` — 화면 범위 계산

DOM 조작과 지도 렌더링은 테스트하지 않는다. 브라우저에서 눈으로 확인한다.

## 10. 확인된 제약

- 용도지역 데이터는 **전남 22개 시군**뿐이다. 그 밖은 판정불가다
- Supabase 무료: DB 500MB(현재 약 200MB), 전송 5GB/월, **1주일 미사용 시 정지**
- Vercel Hobby: 함수 10초, 배포 번들 250MB
- `data/setback_table.csv`가 비어 있어 이격거리는 전 지역 판정불가다. 사람이 조례
  수치를 확정해야 한다 — UI 개편으로 해결되지 않는다
